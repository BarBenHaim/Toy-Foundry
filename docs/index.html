What is real on this page

            
    
                
  • ✓The sculptor. Body plan, eye count, horns and wings become geometry — buildStandInToy, unchanged.
    • 
                
  • ✓The repair pass. Weld, drop degenerate triangles, delete floating fragments, orient every shell outward, scale, stand it on the plate.
    • 
                
  • ✓The print checks. Watertightness, one-part, sampled wall thickness, balance over the footprint, overhang share — all measured, in millimetres.
    • 
                
  • ✓The STL. Written in memory as you watch; the byte count under "Triangles" is the real file size.
    • 
                
  • ✓The prices and the prompt. Same tables, same prompt builder as the live app.
    • 
                
  • ✓Reading the drawing, where your Claude account allows it: the same system prompt and the same normaliser the API route runs, answered by Claude vision on this page.
    • 
                
  • ✓The order flow. Placing one writes a stored record; the status buttons run the real forward-only state machine.
    • 
            

        

        

            
What needs a server

            
    
                
  • —Drawing the toy. The image model renders the collectible-toy version the parent approves.
    • 
                
  • —The sculpt. In production the mesh comes from image-to-3D; this procedural one is the fallback that keeps a paid order alive when that service fails.
    • 
                
  • —Taking money. Stripe Checkout, and the email that carries the only link back to an order.
    • 
                
  • —Production. Handing the STL to a print shop, and the queue a human works it from.

What this is

        

            ToyFoundry turns a child's drawing into a 3D printed collectible toy: read the drawing, design it,
            approve it, sculpt it, check it can actually survive a printer, print it, post it. This page is the
            middle of that pipeline, compiled out of the product's own source and running in your browser — so the
            toy above was welded, repaired, stood upright and measured by the code an order really goes through.
        

        

            The two steps this page cannot do on its own are the ones that need a server: Claude reading the drawing
            into a character record, and the image model rendering the toy. Run the full app and both come alive.
